zram and zswap are one module, `features/nixos-swap`, gated by `features.zswap.enable` (default true, the tier these hosts ship) and `features.zram.enable` (default false). They were separate modules carrying the same tuning block twice, so the shared numbers live once: `sysctlBase` + `sysfsBase` (swappiness, page-cluster, watermarks, lru_gen, THP) plus the `/sys` tmpfiles writer, and each tier adds only what is specific to it. `boot.kernel.sysctl` and `systemd.tmpfiles.settings."10-swap"` arrive when either tier is on, at mkDefault. Hosts opt in by setting the tier's own options (`features.zswap.swapfile.*`, `features.zram.*`, `sysctl`/`sysfs` overrides); writing sysctls beside the feature is what this decision rules out. Note `features.zswap.sysctl`/`sysfs` are worded as tuning only -- a host writing `net.*` there would break nixos-network's `sysctlMerge` (ADR-36d437504c9f), which owns sysctls other than these.

One tier per host, because both compress: zswap compresses pages before they reach a swap device, zram is itself the compressed device, and layering them compresses twice. The module asserts `!(zswapTier && zramTier)`, and the zram tier puts `zswap.enabled=0` on the kernel command line, alongside nixpkgs' own `boot.zswap-vs-zramSwap` assertion. Both enable options default to a tier, so uncommenting `"nixos-swap"` in `hosts/methyl-base/base.nix` for the zram tier needs `features.zswap.enable = false` beside it.

The numbers, as defaults rather than per-host values. Both tiers: `vm.swappiness` 180, `vm.page-cluster` 0, `vm.watermark_boost_factor` 0, `vm.watermark_scale_factor` 125, `/sys/kernel/mm/lru_gen/enabled` `y`, `/sys/kernel/mm/transparent_hugepage/enabled` `madvise` (the sysfs pair written by tmpfiles type `w`). The zswap tier adds `vm.dirty_ratio` 15, `vm.dirty_background_ratio` 5, `vm.vfs_cache_pressure` 100, and the pool knobs (compressor zstd, max_pool_percent 30, accept_threshold_percent 80, shrinker_enabled Y). vm.swappiness moved from 150 to 180 and vm.vfs_cache_pressure from 50 to 100 on the hosts that already run zswap, so this is a live tuning change at the next switch, not a config-only edit.

The swapfile is prepared, not managed. `prepare` orders itself before the `.swap` unit and nixpkgs' `mkswap-<device>` unit, exits early while the swap is active, and otherwise makes the parent directory a btrfs subvolume when the host asked for one. It then wipes that subvolume and marks it NOCOW: `chattr +C` is inheritable, so files created afterwards carry NODATACOW, but it is only takeable while the directory is empty and btrfs cannot set it on a file that already holds data (btrfs-man5) -- so the directory must be cleared before the file is allocated. The wipe is bounded to a directory `btrfs subvolume show` confirms is a subvolume, and a path inside the filesystem root subvolume is refused rather than emptied, because a shared directory is not ours to clear. After that it removes a swapfile whose size, allocation or NOCOW attribute does not match what the options say, so nixpkgs' mkswap unit has nothing unusable to hand to `swapon`. Creation stays nixpkgs' job: its mkswap unit runs `btrfs filesystem mkswapfile` on btrfs and dd + mkswap everywhere else -- fully allocated, which is what XFS needs since it has no COW attribute and a sparse file is rejected there. Its mkswap unit re-runs on every activation and recreates the file whenever the size differs, so a resize is paid at the switch with the old swap still active. `hosts/methyl/nixos.nix` now asks for 16384 MiB where the tree said 4096: that is the resize ADR-29b6090bccd8 declined to take on, and nothing here swaps off first -- mkswap unlinks a file the kernel still holds.

`RuntimeInputs` follows the filesystem the swapfile sits on, not any btrfs mount: btrfs gets btrfs-progs, e2fsprogs (`chattr`/`lsattr`) and findutils (the wipe); ext4 and XFS get none of them. The subvolume rule is `onBtrfs && features.zswap.swapfile.btrfsSubvolume`, so a host that turns the rule off stops requiring NOCOW too. btrfs *support* is not declared here: nixpkgs' filesystems module already feeds `boot.supportedFilesystems` from the declared mounts, and writing it while reading `config.fileSystems` back overflows the stack at eval.

What the gate proves is config shape only. `tests/swap.nix` (19 attributes) asserts the zram generator settings and template unit, the shared sysctl/sysfs on both tiers, the tier-only knobs, a tier override beating the defaults, `swapDevices` and the prepare unit on the zswap tier only, the subvolume default per filesystem, that zswap is on by default, and the gate read back from the assertion list: false when both tiers are on, gone when one is. Nothing asserts the script's behaviour -- `writeShellApplication` shellchecks it, but no VM test runs the wipe, the chattr, or a resize on real btrfs; the tool set it ships with is a build-time fact the eval suite cannot read back. `tests/configs.nix` asserts on the three real hosts that zswap is the on tier, zram is off, and the shared tuning arrived with it (`vm.swappiness` 180 and the `/sys` writer).

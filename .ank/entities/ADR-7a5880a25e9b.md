title: Test proofs come from the declared verifier, not from detached refs
created: 2026-11-05T00:43:27Z
author: josh@methyl-bazzite
status: proposed
scope:
  - .ank/config.yml
  - tests/run.sh
constraint: |
  A task's test proof is produced by the verifier config.yml declares; attestation through detached refs is not used, because a GitHub remote refuses the blob refs refs/ank/proof/* points to
schema: 4
version: 1
---

GitHub rejects a push whose ref points at a blob: `git push origin refs/ank/proof/<id>` is refused with `fatal error in refname rules`, while `HEAD:refs/ank/<name>` (a commit) is accepted. ank's detached attestation writes a YAML blob at `refs/ank/proof/<id>`, so a proof attested with `--detached` can never reach this remote, and the tool's own remedy - `ank attest --proof test:<run-id> --detached` - is not runnable here.
What holds instead: config.yml declares one verifier, `verifiers.gate.run = "bash tests/run.sh"` (default true), so `ank done` runs it and records `type: test, via: verifier` against the run in `.git/ank/runs/`. A verifier-run proof satisfies the `unattested-proof` rule; a proof whose `via` is `submitted` does not, attested or not.
Consequence, stated rather than worked around: the 16 tasks closed before the verifier existed keep their `unattested-proof` signal. Their proof is `commit:<sha>, via: submitted`. Re-attesting them into the entity file only changes the wording of the signal, so it is not done.

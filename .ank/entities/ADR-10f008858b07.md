The symlink guard runs first: features/*/update.sh entries that are copies, not symlinks, stop the
run before any pin moves. The commit is staged from features and flake.lock only, so a run on top
of unrelated work-in-progress is skipped rather than bundled into a chore commit; a clean index
after staging commits nothing.

Forwarding every argument except --flake keeps --check working across all features, which is what
makes the updater usable as a CI probe.

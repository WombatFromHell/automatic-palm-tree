credsctl owns the store (list, encrypt, decrypt, decrypt --env, rm) and exit codes 1 usage / 2 no
such record / 3 encrypt or decrypt failed; sopsctl owns every sops detail and credsctl never
repeats one. The store is ~/.local/share/credentials, or CREDENTIALS_DIRECTORY inside a generated
unit — the same chain xilo reads. CREDS_DIR moves it for credsctl only, which is why a unit sets
CREDENTIALS_DIRECTORY and not CREDS_DIR.

The suffix is the shape on disk: a name plus suffix picks the backend, so XILO_URL.sops.json is
preferred over XILO_URL.cred, and a bundle record (XILO.sops.json) fills every key nothing else
covers. systemd-creds stays the backend for secrets a unit mounts, because a .cred is sealed to
this machine and one decrypt buys one secret.

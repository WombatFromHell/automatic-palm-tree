Retires ADR-a4a979e59a3d, whose "every other file in a feature directory is not a module" still binds beside its amendment ADR-60a85c263af2 while several such files are modules. The amendment stays accepted and states this rule correctly; this entity carries the same rule so the superseded wording stops binding. --supersedes names one document, and edit cannot repoint it, so the pair cannot be retired by a single entity; retiring the amendment too would add a second binding copy of the same rule.

Measured: lib/features.nix:21-24 discovers only the names nixos, home and _overlays. The extras reach a host only where a platform module names them: features/nixos-niri/nixos.nix:22-24 imports ./_niri.nix and ./_niri-portals.nix, features/nixos-niri/_niri.nix:10 imports ./_niri-session.nix, features/nixos-niri/home.nix:3 imports ./_wl-watcher.nix, features/nixos-kde/home.nix:8 imports ./_theme.nix. Files that are not modules are reached the same visible way: features/nixos-niri/nixos.nix:10 and :16 import ./_desktop.nix and ./_spicy.nix as functions, and features/nixos-gaming/nixos.nix:2-3 callPackage ./_nscb_pkg.nix and ./_protonfetcher_pkg.nix.

Read literally, the old wording forbids exactly the pattern these features use, so a contributor would split or rename them. The boundary worth binding is discovery: an extra file cannot reach a host by itself, only where the feature's own entry point names it, which keeps the import visible in the feature.

builtins.tryEval reports success for a deferred error, because the error is a value until it is
forced. So the red guards are separate files the gate evaluates and expects to fail, and the
substring they must name is the first line of the file.

A newcomer writing tryEval (throw "...") in a green suite gets a passing test for a bug that is
still there.

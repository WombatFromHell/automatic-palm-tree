A record is one file, and both spellings reach it: `ALPHA`, `ALPHA.cred`, `./ALPHA.cred` and
`./ALPHA.sops.yaml` are the same record, resolved by `record_for`.

- `decrypt` with one argument is that file: a sops record prints its whole json map, a `.cred` prints
  its secret exactly as its name would, and a file of no record shape is refused (2). Every other form
  is a list — `decrypt NAME [NAME...]`, `decrypt ./A.cred B` — and each entry prints its secret, one
  record per line. A path leading the list no longer stops the entries behind it, which is what the
  old single-path dispatch dropped silently, and a `.cred` path is no longer refused as "not a sops
  record" while `get`, `verify` and `recipients` still refuse it (sops has no format to read it with).
- `--env` keys are the record's basename; a basename no shell can name (`MY.TOKEN`) is refused, and a
  path is accepted there too because its basename is the variable.
- `encrypt` seals the store's plaintext file when a bare sops-shaped name has one, otherwise streams
  one secret from a prompt or a pipe. A seal that fails names the seal and defers the reason to sops'
  stderr: the same exit 3 covers a plaintext that is not a map and a rules file with no matching
  creation rule, so credsctl must not pick a cause it cannot see.
- `reset` globs `$CREDS_DIR`, the store the commands read. `CREDS_DIR` can point away from
  `CREDS_ROOT` (a unit's `CREDENTIALS_DIRECTORY`), and globbing the rules file's directory would
  delete records nobody is using while leaving the records in use alone.

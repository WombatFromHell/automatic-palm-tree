The 21:43 OOM kill of the local model server was systemd-oomd, not the tier's own cap: the journal
marks the model server's scope for killing at 87% of RAM *and* 87% of swap, and the tier's own
scopes run at MemorySwapMax=0, so they cannot swap at all. Every kernel kill in the window is a
CONSTRAINT_MEMCG kill of our own pack-import/sqsh scopes. The fix is a precondition the tier checks
itself: vm_headroom_check reads the host's own meminfo (VM_MEMINFO stands in for it in tests) and
refuses when free RAM is under cap + a gigabyte, or swap is under a gigabyte whenever the host has
swap at all — oomd's own condition, checked before anything boots.

The second defect is the push pair: bats runs each test in its own process, so the file-scope
push_log in shared_push_run never carried from one test to the next, and the drive-boot test booted
a second full push guest — five extra minutes and a widened OOM window on every gate run. The
handoff is a file in the scratch dir: the completed run's log, only accepted when that log proves
the drive install succeeded, so a stale value can never turn a failing tier green.

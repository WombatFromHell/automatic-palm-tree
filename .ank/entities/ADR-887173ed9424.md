disko is retired (commit 60bcd4e): `features/nixos-disko`, `tests/disko.nix` and the `disko` input
are gone, and `install.sh` no longer reads `c.disko.devices`, an option that no longer exists.

ADR-eaca61b85782 gated disko's `gpt` content on `ownsWholeDisk` because disko, for each partition
index it names, tries `sgdisk --new` and on failure falls back to `--partition-guid`,
`--change-name` and `--typecode` on whatever already sits at that index. On a drive shared with
Windows that rewrites the boot metadata of a partition disko never created. The gate held, but the
tool it gated was never the thing this flake deploys with: every host now declares its layout as
`hosts/<host>/terraform.json` and terraform.sh reproduces it (ADR-b77ec913151f, ADR-62773e12d275).
The recipe states ownership itself — `owns` — and terraform.sh writes a fresh gpt table only where
that is true, appending partitions into free space otherwise, so the fact that made the guard work
moved from a module assertion to the recipe and the checks in `tests/configs.nix` that read it back.

Deleting the feature left one dangling reference in the deploy path: `install.sh --stage prepare`
evaluated `c.disko.devices` as its fifth fact and refused a host that declared a layout with no
installer. With the option gone that eval throws, so the fact and the refusal are deleted; the
surviving refusal is the one that matters — a host with no recipe, or a recipe whose `owns`
disagrees with `flakeHost.ownsWholeDisk`, stops before anything runs. The check that replaces the
disko one is the check that can actually fail: `tests/configs.nix` refuses a leftover
`features/nixos-disko` directory or a `disko` string anywhere in `flake.nix`.

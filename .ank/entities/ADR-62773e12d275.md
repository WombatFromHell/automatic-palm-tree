Today the two directions agree by assertion: hosts/methyl-nixos/nixos.nix hand-writes device, fsType and options, and tests/configs.nix checks them against hosts/methyl-nixos/terraform.json as a subset (labels become devices, recipe options must be a subset of the config's). That holds only while someone remembers to edit both files: a recipe edited by terraform.sh --emit, or a label changed there, leaves a config naming a device the run will not create, and the failure surfaces at boot, not at eval.

So the recipe is read during eval instead. builtins.fromJSON (builtins.readFile ./terraform.json) costs nothing (the file is already read by tests/configs.nix and by terraform.sh), and the derived mounts cannot disagree with it. A flake app that prints a declaration was considered and rejected: builtins.toJSON gives JSON, not Nix source, so emitting a .nix file needs a pretty-printer that does not exist, and the emitted file is a second source of truth that goes stale the moment the recipe is edited -- which is the exact drift this closes.

The direction of the options rule flips for partition mounts. ADR-3d236ece09d6 made terraform.sh mount with whatever hosts/<host>/nixos.nix declared and --emit copy that; now the recipe holds the options and the config reads them, so the copy --emit made is the origin. mount_opts stays as the fallback for an entry declaring nothing, and its filesystem-scoped defaults stay exactly as measured: btrfs noatime,compress=zstd, vfat fmask=0077,dmask=0077, ext4 noatime only (terraform.sh:116-140). An entry declaring options "" means the kernel's defaults -- splitString "," "" yields [""], so the empty piece is filtered rather than passed to mount.

Two refusals are new, because both lose a mount silently today: listToAttrs and // drop the second entry when two partitions claim one mount point, and an unlabelled partition has no device name to write (terraform.sh --emit leaves the label out when the filesystem has none, terraform.sh:442-454). Both throw naming the partition. A partition with no mount is skipped: terraform.sh still creates it, NixOS does not mount it.

What stays host-side is the btrfs subvolume tree -- @, @home, @nix, @log, @cache, @swap, @snapshots. terraform.sh creates that tree by names fixed in ADR-eaca61b85782, not from the recipe (terraform.sh:688-697), so deriving every mount from the recipe needs the recipe to carry subvolumes first. That is a separate slice with its own amendment: hosts/<host>/terraform.json gains subvolumes on the btrfs root entry, create_subvolumes reads them, --emit lists them when the root is mounted (btrfs subvolume list, otherwise an operator's edit), and the host's sugar block deletes.

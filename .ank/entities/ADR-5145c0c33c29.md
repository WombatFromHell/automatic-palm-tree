The old text demanded writeShellApplication plus builtins.readFile for every helper. Four helpers
use it; pinentry-tmux, pinentry-zellij and nasmount-sshfs do not, deliberately: runtimeInputs
rewrites PATH inside the script and would pull tmux, zellij and sshfs into the hm-gpg and
hm-nasmount closures that the interactive session supplies today. That is a behaviour change, not
a coverage gain - all three already report zero shellcheck findings.

What the rule actually protects is that shell reaching a host was linted. writeShellApplication
gets that from nixpkgs' checkPhase, and tests/shellwrap.nix asserts runtimeInputs and substituted
markers for the wrapped ones. For the unwrapped ones the gate now lints them directly
(shellcheck -f gcc over pinentry-tmux.sh, pinentry-zellij.sh, nasmount-sshfs.sh, lib/updater.sh,
bootstrap.sh and update-all.sh, any finding failing the gate). The scope's features/*.sh glob
matched no tracked file; features/*/*.sh is the shape that does.

Known gap kept on purpose: inline text passed to writeShellScriptBin - hm-gpg's pinentry-fallback -
is not linted by that pass. Closing it means routing the text through a wrapper the gate builds.

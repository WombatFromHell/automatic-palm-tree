install.html gives two routes: npm (`npx ank-cli`, whose Linux asset is musl) and a fallback
`cargo install --git https://github.com/haksolot/ank ank-cli` that the page itself flags as landing
the binary in `~/.cargo/bin`. Neither belongs in this flake. features/hm-ank pins the source as a
nar (ADR-0b73, ADR-8b56), builds it with rustPlatform.buildRustPackage over fetchFromGitHub, and
puts the result in home.packages, so the binary is a store path on PATH and nixpkgs' own
CARGO_HOME keeps every cargo artifact inside the build directory.

Cargo.lock is committed and carries no git sources, so the derivation uses cargoLock.lockFile and
has no cargoHash (ADR-0b73). cargoBuildFlags = ["-p", "ank-cli"] is what makes the build mean
`cargo install … ank-cli`: the workspace also auto-discovers src/bin targets in ank-core and
ank-contract, so an unrestricted build would put four internal tools (config-keys, entity-fields,
environment, exit-codes) on PATH beside the CLI. env.CARGO_NET_OFFLINE = "true" states the vendored
contract. doCheck = false because upstream's suite drives real git corpora and git is not in this
build environment; the shortcut is recorded in the derivation and upgrades by adding pkgs.git to
nativeBuildInputs. meta.platforms is pinMeta.pinnedSystems pin (ADR-0b73).

It builds from the stable set, not pkgs.unstable: Cargo.toml requires rust-version = "1.95" and the
pinned nixpkgs is rustc 1.95.0, and unstable is the convention for tracking packages (ADR-3611).
The package travels through the package set, reached by callPackage, not an overlay (ADR-380b), and
features/hm-ank/update.sh is the lib/updater.sh symlink whose URL expansion is byte-compared with
lib/pin-meta.nix by the gate (ADR-122a, ADR-ba1f). The page's `npx skills add haksolot/ank` step is
out of scope: skill files are the user's own.

Consequences: ank is on PATH for methyl and methyl-nixos (hosts/methyl-base/extras.nix) and
methyl-bazzite (hosts/methyl-base/standalone.nix); propyl stays out, since it takes the
methyl-common home profile. Upstream's `ank self-update` is not used — updates go through the pin.
mise prepends its own shim directory, so an npm copy under
~/.local/share/mise/installs/node/24/bin/ank still wins `which ank` until that file is removed;
this feature never deletes it.
